What This Demonstrates

  • Implicit task creation: <aft-data id="x" src="..."> automatically creates and manages $tasks.x — no extra markup needed
  • Task state: $tasks.x.pending, $tasks.x.error, and $tasks.x.startedAt are reactive and usable in any binding expression
  • Shared task state: a button declaring aft-task="x" participates in the same task slot as the <aft-data id="x"> initial load — one indicator covers both
  • Concurrency policy: aft-policy="restart" cancels an in-flight request when a new one is triggered; use drop to ignore new attempts while one is pending
  • $reload(id): context function that re-fetches a data source by id, updating $tasks.<id> just as the initial fetch does
